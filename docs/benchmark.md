# Ranking benchmark foundation

`pnpm test` runs the existing synthetic provider-repository regression suite and prints one machine-readable `CREAMSODA_BENCHMARK_JSON=` line. The v1 report contains per-query paths and Hit@5, Precision@5, Recall@5, and reciprocal rank, plus their aggregate means. It scores unique file paths rather than individual chunks. A missing result counts against Precision@5.

The corpus is generated in `packages/testing/src/ranking-eval.test.ts`. Its seven queries and declared relevant paths are public, synthetic development fixtures—not proprietary evaluation data, a held-out test set, or evidence of real-world performance. Existing top-k and source-over-artifact assertions, a Hit@5 gate of 1.0, a synthetic MRR@5 floor of 0.85, and repeated-ranking determinism are CI gates. These are regression checks for this toy fixture, not product-quality claims. Reports contain no source excerpts or provider credentials.

Next steps: collect larger, separately reviewed repositories and judgments from more varied codebases, then set defensible quality thresholds after recording repeated baselines. Keep any private customer corpus outside the public repository, subject to consent and retention rules.

## Public evaluation split

`packages/testing/src/heldout-fixtures.ts` contains two small synthetic repository shapes (checkout web app and background worker). Twelve separately declared query judgments in `heldout-judgments.ts` are disjoint from the seven development queries. These public fixtures are held out **from development tuning** only; they are visible in the repo, neither secret/proprietary nor representative of real customer code. Do not tune retrieval against this split or treat it as an unbiased generalization estimate after tuning.

`pnpm test` runs Cream Soda retrieval in deterministic `exact` mode and a dependency-free binary token-overlap baseline over the **same indexed files, queries, labels, and K=5**. `CREAMSODA_PUBLIC_EVAL_JSON=` reports reviewed SHA-256 of fixture contents and judgments, SHA-256 of the compiled retrieval module, indexed file counts, aggregate metrics, and small per-repository and per-intent slices. Both systems use unique file paths, and missing results count against Precision@5. The report deliberately omits per-query text, labels, source excerpts, and credentials so that the output format can be reused with a future access-controlled corpus. The test ensures fixture integrity and result accounting but imposes no quality threshold on this new split; record and review the baseline before setting one. The score of these twelve simple synthetic questions is not a product-quality estimate. The test writes only its own small, known fixtures to an owned temporary directory; it is **not** a safe runner for arbitrary or customer repositories. A public repo cannot host private judgments. Never print or commit private customer fixtures to CI, and review consent, retention, file limits, and sensitive path handling before any private-corpus run.
