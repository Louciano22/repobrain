# MCP trust boundary (first hardening slice)

In stdio mode, the host must launch Cream Soda with its working directory set to the one repository it authorizes. The server canonicalizes that root on startup, rejects selection of a different `repo` argument, and forces tool calls to the launch root. This argument-level pin is not a filesystem sandbox. `clear_index` is not advertised or callable through stdio; operators can still use the explicit local runner. Stdio stdout is reserved for JSON-RPC protocol messages.

This is a first boundary, **not a complete sandbox**. The direct local `--tool` runner remains an operator-facing path. The indexer rejects symlinked roots and existing project store entries, skips discovered symlinks, enforces default sensitive paths even if config removes them, and bounds `.gitignore` (128 KiB and 256 patterns), config size (128 KiB), individual source files (2 MiB), total source bytes (32 MiB), and traversal (50,000 entries, 20,000 source files, depth 40). Rejected oversized input does not update the index store. The existing local store is operator state and is not yet size bounded. These are safety limits, not proof of containment against a concurrently mutating repository: intermediate directories and `.repobrain` can change between checks and opens/writes. The current `.gitignore` handling is a subset, not an exact Git implementation. Redaction is heuristic and ordinary source may contain secrets. Do not grant the MCP process access to unrelated private files or provider keys while these boundaries remain incomplete.

Regression coverage: `packages/testing/src/stdio.test.ts` performs a real initialize/list/call exchange, indexes the launch root with the `repo` argument omitted, rejects an outside repository, denies `clear_index`, and checks that stdout contains protocol JSON only.
